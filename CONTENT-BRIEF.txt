PART 0 - RULES THAT APPLY TO EVERYTHING
==============================================================================

0.1 LATEX ESCAPING - READ THIS FIRST, IT HAS BROKEN THE BANK BEFORE

  Math is written in LaTeX inside $...$ (inline) or $$...$$ (display).
  When LaTeX goes inside JSON, every backslash must be DOUBLED.

    WRONG:   "stem": "Simplify $\frac{1}{2}$"
    RIGHT:   "stem": "Simplify $\\frac{1}{2}$"

  Why this matters more than it looks: in a JSON string \f is the form
  feed character. A single backslash turns \frac into an invisible
  control character, the JSON still parses, nothing throws, and the
  student is shown broken output. 297 questions once shipped that way.
  The same trap applies to \t (\times, \text), \b (\begin) and \r
  (\right).

  If you are writing a .ts file rather than raw JSON, the same rule
  applies inside the string literals.

0.2 LATEX THAT IS ALLOWED

  Use only what KaTeX renders: \frac \sqrt \cdot \times \div \pm
  \le \ge \ne \approx \pi \theta \sin \cos \tan \log \ln
  \underline \text \circ \infty ^{ } _{ } \left( \right)

  Never use: tabular, itemize, align, \begin{array} unless certain,
  \(...\) delimiters, raw carets outside math, * for multiplication,
  -> for arrows, or Unicode math glyphs. Write \pi not the pi symbol,
  \sqrt{2} not the root symbol, x^{2} not a superscript two.

0.3 WRITING STYLE - THE WHOLE POINT OF THIS PROJECT

  The reader is a student who found school maths hard and is preparing
  for a placement test that decides which course they can take. Write
  for them, not for a mathematician.

    - Eighth grade reading level.
    - Define every symbol in words before using it.
    - Show each rule with a concrete number FIRST, then the general form.
    - One idea per paragraph. Short sentences. Under 25 words each.
    - Say why a step is allowed, not just what changed.

  BANNED WORDS AND PHRASES (the verifier rejects these):
    hence, thus, it follows that, observe that, clearly, obviously,
    trivially, denote, arbitrary, straightforward, simply note,
    as we know, recall that

  No em-dashes as sentence connectors. No emoji. Plain full stops.

PART 1B - GRAPH AND DIAGRAM SPECS
------------------------------------------------------------------------------

Use a graph where the shape IS the idea: slope, parabolas, asymptotes,
transformations, inequalities on a number line, the unit circle. Do not
decorate a lesson with a graph that adds nothing.

  Cartesian:
    { kind: "cartesian",
      description: "<what a sighted reader would see>",
      viewport: { xMin: -10, xMax: 10, yMin: -10, yMax: 10 },
      curves: [ { fn: "x^2-3", label: "y = x^2-3",
                  color: "primary"|"accent"|"muted", dashed: false } ],
      points: [ { x: 1, y: 2, label: "(1, 2)", open: false } ],
      segments: [ { from: {x:1,y:2}, to: {x:4,y:2}, dashed: true } ],
      regions: [ { fn: "2x+1", side: "above"|"below" } ] }

    `fn` is NOT LaTeX. It is a plain expression: + - * / ^ ( ),
    x, sin cos tan asin acos atan log ln sqrt abs exp, pi, e.
    log is base 10, ln is natural. Implicit multiplication (2x) is fine.
    Named parameters are allowed via params: { a: 2, h: 1, k: -3 }.

  Number line:
    { kind: "number-line", min: -5, max: 5, description: "...",
      marks: [ { at: 3, open: true } ],
      intervals: [ { from: 3, to: 5, openFrom: true } ] }

  Unit circle:
    { kind: "unit-circle", description: "...",
      angles: [0,30,45,60,90], highlight: 30 }

  Diagrams (geometry figures, labels carry the measurements):
    { kind: "triangle", sides: ["3","4","5"], angles: [...],
      rightAngleAt: 0, description: "..." }
    also: rectangle {width,height}, square {side},
          circle {radius|diameter}, trapezoid {top,bottom,height},
          cylinder {radius,height}, cone {radius,height,slant},
          sphere {radius}, prism {width,height,depth}

PART 3 - ANSWER KEY VERIFICATION
==============================================================================

No human has ever checked the answer keys. The seeding script's own
30-question audit put the wrong-key rate at 6.7 percent, which is
roughly 230 wrong answers across 3,435 published questions. Three are
confirmed wrong by hand.

This is the highest value work in this document. A wrong answer key
teaches the student the wrong thing and they have no way to know.

METHOD - do not skip the first step:
  1. Solve the question from scratch WITHOUT looking at the given answer.
  2. Only then compare with the key.
  3. If they differ, say so. Do not talk yourself into agreeing.

Reading the key first produces agreement with whatever is there, which
is worse than not checking, because it looks like verification.

OUTPUT: one line of JSON per question.
  {"id":"q_...","agrees":true}
  {"id":"q_...","agrees":false,"correct_answer":"...","why":"..."}

Batches of 25 to 50 questions work well. Export a batch with:

  npx tsx scripts/export-verify-batch.ts --offset 0 --limit 50
